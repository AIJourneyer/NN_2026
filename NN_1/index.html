1 The big picture: where neural networks fit

Classical machine learning (linear and logistic regression, KNN, decision trees, gradient-boosted trees, SVMs) works on tabular data: a table with rows (samples), feature columns F1 … Fn and usually a target column y.

Deep learning uses neural networks (NN), which can also handle images, text and sound.

FamilyBest forWhy it exists
Basic / feed-forward NNAny numeric inputsThe foundation of everything below (this page)
CNN (convolutional NN)ImagesImages have a spatial property: a pixel is related to the pixels around it
RNN (recurrent NN)Text, sequencesEach word depends on the words around it
GAN (generative adversarial network)Generating new dataTwo networks compete, like a forger and a detective
TransformersText, images, speechPower GPT and multimodal models
Common confusion: does deep learning contain neural networks, or the other way round?

You will see diagrams that draw deep learning as the bigger bubble. The usual definition is: deep learning = neural networks with many hidden layers, so deep learning sits inside (or is another name for) neural networks. Transformers are separate from CNNs and RNNs, but all three are neural networks.

Common confusion: is Stable Diffusion a transformer?

Not exactly. Stable Diffusion is a diffusion model: it uses a transformer text encoder, and its image-denoising network is a U-Net in versions 1–2 and a transformer in version 3. "Contains transformers" is right; "is a transformer like GPT" is not.

CNNs, RNNs and Transformers are all neural networks. The simple feed-forward network on this page is the building block for all of them.

2 Why classical ML struggles with images and text

2.1 An image is a grid of numbers

  • An image is made of pixels, small squares that each hold a number from 0 to 255. A handwritten digit from the MNIST dataset, for example, is just a 28 × 28 grid of these numbers.
  • Why 0–255? One colour channel is stored in one byte = 8 bits. 8 bits give 2⁸ = 256 combinations; counting from 0 gives 0 … 255. The bit values are 128, 64, 32, 16, 8, 4, 2, 1, and all of them together make 255.
  • In grayscale, 0 = black, about 128 = mid gray, 255 = white (brightest).
  • A colour pixel is three numbers: R, G, B (red, green, blue). Any colour can be mixed from them. All three at 255 gives white; all at 0 gives black; a dark red pixel has a high R and low G and B.
  • Models want standardised inputs, so pixel values are usually divided by 255 to land between 0 and 1.

2.2 There are no fixed features in an image

Classical ML needs features (useful input columns), and somebody has to create them. For a cat-vs-dog classifier, which columns would you make?

  • A cat looking at you, sitting the other way, rotated or upside down is still a cat. No single hand-made measurement survives all of these.
  • The same street photographed at −2, normal and +2 exposure looks like three different images to a model, even though it's the same scene.
  • The old approach was hand-built edge detectors. They break when resolution, brightness or orientation change.
Aside: pixels vs polygons in video games

Old games like the 1996 Tomb Raider look blocky; modern ones look photo-real, but both are still built from small flat pieces. Those pieces are polygons (a 3D mesh of small triangles), not pixels: the blocky look came from a low polygon count, and the finished frame is then drawn as pixels on screen.

2.3 Text needs context

Classical text models look at individual words ("good", "bad"). Real sentences don't work that way:

SentenceWhy word-counting fails
"The food was not great, but not terrible"Mixed: needs context
"I love cats. I hate this movie."Both "love" and "hate": sentiment depends on what is being talked about
"It was good. Really good. Totally good."Repetition adds emphasis
"Best worst movie ever"Contradictory words
"Can't wait to never see this again"Negation plus sarcasm
"That was sick" vs "I feel sick"Same word: positive slang vs negative literal meaning
"Yeah, great job…"Sarcasm: tone flips the meaning

Classical ML is only as good as the features you give it. For images, video, audio and text, good hand-made features are close to impossible to design.

3 Hand-made features vs learned features

3.1 The two pipelines

In classical ML: raw data → you create features (using experience and domain expertise) → select the best ones → train a model. In deep learning: raw data → the network creates the best features itself, based on the data and the target.

A kitchen analogy: classical ML is cooking from a recipe that needs every ingredient cleaned, cut and measured by an expert. A neural network is happy with khichdi: hand it the raw mix and it works out the useful parts itself.

3.2 The circle experiment

A classic test (you can run all three rows yourself in the playground in Section 11, or on TensorFlow Playground): blue dots in the middle, orange dots in a ring around them.

SetupResult
1 neuron, no hidden layer, inputs x1, x2Only a straight-line boundary. This set-up is a linear model.
Same, plus x1², x2² as extra inputsA circular boundary. Still a linear model; this is polynomial regression: the curve comes from the features you added.
Hidden layers, non-linear activation, inputs x1, x2 onlyA circular boundary, with no extra features. (Sigmoid hidden units learn much more slowly here than tanh or ReLU: see preset 6.)

Question: Why is a neural network better than polynomial features, in efficiency or accuracy?

Answer: It's about possibility, not efficiency. Here two squared features happened to be enough, but for real data nobody can work out which higher-order features are needed. A network finds them by itself.

Question: Do we still need to give the network some features?

Answer: Yes, the basic raw inputs. For example, give it height and weight; it can then build combinations like a BMI-style feature by itself.

3.3 Universal function approximator

Neural networks are called universal function approximators: with enough neurons, data and good-quality inputs they can, in theory, approximate any function. (SVMs with an RBF kernel share a similar theoretical property.) In practice, the amount of data and how well training goes limit what you actually get.

Going further

This comes from the universal approximation theorem (Cybenko 1989; Hornik 1991): a network with one hidden layer and enough neurons can approximate any continuous function on a bounded range. It says nothing about how much data you need or whether training will actually find those weights.

A linear model needs you to add higher-order features to bend its boundary. A neural network bends the boundary itself from the raw features.

4 When to use classical ML vs a neural network

4.1 Data decides

Real projects depend on data quality, budget, number of features and problem complexity. The classic data-vs-performance picture:

  • With little data, traditional ML tends to work well, often better.
  • With more data, a small neural network pulls ahead, because it can build better features from more examples.
  • With even more data and a bigger network, accuracy keeps rising.

4.2 A practical rule of thumb

DataUseWhy
Tabular (rows × columns)GBDT-based algorithms: XGBoost, LightGBM, CatBoostMost winning Kaggle solutions on tabular data use a gradient-boosting variant
Images, text, audioNeural networks (CNN, RNN, Transformer)Features can't be hand-made
Small datasetClassical ML / GBDTNot enough data for a network to learn good features
Decent → lots of dataSmall NN → large NNBigger networks need and use more data

"Large" is relative: a 100-layer model is big for most teams, while frontier labs train far bigger ones. For scale, GPT-3 (175 billion parameters) has 96 layers; parameter count and data size usually matter more than the layer count.

Don't over-engineer

Using deep learning on a simple problem is like cutting your dinner with a huge sword. If the data is a small table, start with GBDT.

Question: Can a neural network ever beat GBDT on tabular data?

Answer: Yes. There is no fixed rule: if the hand-made features are poor, GBDT suffers and a network can do better. In general, GBDT works better on tabular data.

Tabular → GBDT. Images or text → neural network. More data → bigger network.

Going further: what is an autoencoder?

An autoencoder is a network that squeezes its input into a small code (encoder) and rebuilds the input from that code (decoder). To rebuild well, the code must capture the general pattern of the data, which is why it is used for compression and for finding meaningful structure.

6 Inspiration: the biological neuron

6.1 Neurons fire only for specific signals

Our brains have billions of neurons that pass information from one to the next. But a neuron does not fire for every signal. Classic evidence comes from David Hubel and Torsten Wiesel (late 1950s; Nobel Prize 1981): electrodes recorded one neuron in a cat's visual cortex while bars of light at different angles were shown on a screen.

  • The neuron fired a lot for a vertical edge, a little for slightly tilted edges, and not at all for horizontal ones.
  • So each neuron is tuned to respond to a specific kind of signal. This idea later inspired CNNs.

6.2 Two brain myths and a meme

  • "We only use 10% of our brain" is a widely debunked myth. Different parts are active for different tasks: while you listen to someone, the hearing and vision areas are busy and the leg-control area is quiet. Over a day you use all of it.
  • The "three brain cells I brought to my exam" meme gets one thing right: capability comes from having many neurons working together. The human brain has roughly 86 billion of them.

6.3 "Neurons that fire together wire together"

This summarises Hebb's rule (Donald Hebb, 1949): connections between neurons that are often active together get stronger, and practised pathways become faster (the insulating myelin sheath also adapts with practice). A skill you never revise fades. The same mechanism explains why cravings in addiction trigger an action almost instantly.

Study tip

Use this on yourself: revise for 10 minutes every day at a fixed time, grow it to 15–20 minutes after a week, and don't go above 30. Short and consistent beats long and occasional.

The neural-network version: if an input is important, the neuron gives it a bigger weight (a "thicker connection"); if it is unimportant, a small weight.

A neuron only passes on the signals it is tuned for. In a network that tuning is stored in its weights.

7 The artificial neuron

A neuron in a neural network takes inputs x1, x2, …, which are features (columns, not rows). It learns a weight for each input plus one bias, computes a weighted sum, then applies an activation function.

z = w₁x₁ + w₂x₂ + … + wₙxₙ + b = Σ wᵢxᵢ + b

a = f(z) (the neuron's output)

TermMeaning
Weight wᵢHow much input i matters (and in which direction, + or −). Learned.
Bias bA learned constant that shifts the weighted sum, like the intercept c in y = mx + c. Without it, every boundary would have to pass through the origin.
zThe weighted sum, also called the linear combination or "score".
Activation fA function applied to z. Its main job is to add non-linearity (Section 8).

Two special cases link this to models you already know:

One neuron with……is exactly
Linear activation (f(z) = z)A linear model (linear regression)
Sigmoid activationLogistic regression (score → probability → yes/no at 0.5)

7.1 Example: should I touch this object?

Two inputs: temperature T (0 = cold, 1 = hot) and familiarity F (0 = unknown, 1 = very familiar). Heat should push toward "no" (negative weight, −2), familiarity toward "yes" (positive weight, +1.5), and the bias is +0.5. So z = −2·T + 1.5·F + 0.5 and p = σ(z); touch if p ≥ 0.5.

ObjectTFzp = σ(z)Decision

Try: (1) drag the bias up and watch the dashed boundary slide while its angle stays the same: the bias shifts; (2) change wT or wF and the boundary rotates; (3) flip wT to positive: hot objects now look safe. However you set them, one neuron can only ever draw one straight line.

Common confusion: a positive bias is not "caution"

It's tempting to read the +0.5 bias as "slightly cautious". It's the opposite: adding +0.5 to z raises the probability of touching for every object. A cautious neuron would have a negative bias. Drag the bias slider to see it.

A neuron = weighted sum + bias, then an activation. With sigmoid, a single neuron is logistic regression and draws one straight boundary.

8 Why we need activation functions

8.1 Without activation, layers collapse

Chain two neurons: feature F1 goes into N1 (weight 3, bias b1), whose output goes into N2 (weight 5, bias b2), with no activation:

N1 = 3·F1 + b1

N2 = 5·(3·F1 + b1) + b2 = 15·F1 + (5·b1 + b2)

15 and (5·b1 + b2) are just constants → call them w3 and b3 → N2 = w3·F1 + b3

Two neurons became one neuron with weight 15. The same happens with 100 or 200 linear layers: any chain of linear steps is still one linear step, so it can only draw a straight line. (Preset 4 in the playground shows this live.)

8.2 With activation, they don't

Put a sigmoid σ after each neuron:

N1 = σ(3·F1 + b1)

N2 = σ(5·σ(3·F1 + b1) + b2)

Because σ is non-linear, you can no longer pull the constants out; the two neurons stay genuinely different. A quick check: equal steps in z do not give equal steps out of σ.

σ(5) = 0.99331, σ(10) = 0.99995, σ(15) = 0.9999997

σ(10) − σ(5) = 0.00665  ≠  σ(15) − σ(10) = 0.0000451

The spaghetti picture

Raw spaghetti is straight (linear). Cooked spaghetti bends. The activation function is what lets the network "bend" its combinations of features.

8.3 Common activation functions

FunctionOutput rangeNotes
Sigmoid σ(z) = 1/(1+e−z)0 to 1Great for an output probability; in hidden layers its gradients get very small, so learning is slow (playground preset 6)
tanh−1 to 1Zero-centred cousin of sigmoid; TensorFlow Playground's default

Coming in the next part

The choice of activation changes the gradients used for learning, which leads to the vanishing and exploding gradients problem.

Activation functions let a network form non-linear combinations of features. Without them, any number of layers equals a single linear neuron.

9 Layers: wiring many neurons together

9.1 Fully connected layers, every parameter labelled

Each feature is connected to every neuron in the first layer, and each connection has its own weight. Each neuron is then connected to every neuron in the next layer. This is a fully connected (dense) feed-forward network. Below, every one of its 14 weights and 6 biases is numbered.

NeuronIncoming weightsBiasWhat it computes
N1w1 (from F1), w2 (from F2)b1a1 = f(w1·F1 + w2·F2 + b1)
N2w3 (from F1), w4 (from F2)b2a2 = f(w3·F1 + w4·F2 + b2)
N3w5 (from F1), w6 (from F2)b3a3 = f(w5·F1 + w6·F2 + b3)
N4w7 (from N1), w8 (from N2), w9 (from N3)b4a4 = f(w7·a1 + w8·a2 + w9·a3 + b4)
N5w10 (from N1), w11 (from N2), w12 (from N3)b5a5 = f(w10·a1 + w11·a2 + w12·a3 + b5)

9.4 Design facts

  • The number of neurons in a layer is independent of the other layers. You could feed 10,000 features into 3 neurons, and then have 10,000 neurons in the next layer.
  • A common pattern: more neurons in early layers (many primitive features), fewer in deeper layers.
  • Weights start random and are then improved by gradient descent (weights move in the direction that reduces the loss).
  • For multi-class output, the last layer has one neuron per class (Section 12).

Question: Every neuron gets the same inputs. Won't they all learn the same weights?

Answer: No, because weights are randomly initialised, so each neuron starts somewhere different and back-propagation pushes each one differently. If they all started with the same weights, they would indeed stay identical (the "symmetry" problem).

Question: If a neuron's activation output is 0, won't everything after it be 0?

Answer: No. The next neuron also receives the outputs of all the other neurons in the layer. But a neuron that always outputs 0 is useless: nothing can be built from it (with ReLU this is called a "dead" neuron).

Common confusion: what "fully connected" means

It does not mean every neuron is connected to every other neuron. In a standard dense network each neuron connects to every neuron in the next layer only: no links inside a layer and none that skip layers (unless the architecture adds "skip connections", as in ResNet). It is also not mandatory: CNNs, for example, are only locally connected.

Common confusion: one bias per layer?

In standard dense layers each neuron has its own bias, so a layer has a bias vector (b1, b2, b3 above). A Keras Dense(64) layer, for example, has 64 biases.

Count weights layer by layer as inputs × outputs, and add one bias per neuron. Random starting weights are what let neurons learn different things.

10 How depth builds complex decision boundaries

10.1 Lines → bends → shapes

Inside a first-layer neuron the computation is f(w1·x1 + w2·x2 + b): the part inside f is a linear combination, so each first-layer neuron can only draw a straight line. The second layer receives all those outputs and can combine them, giving slightly non-linear boundaries (corners, bends). Deeper layers combine those again into more complex shapes.

  • Watch it happen in the playground: the small squares in each hidden layer show what each neuron "sees". First-layer squares are always split by a straight line; later layers show curves and blobs that nobody provided: the network engineered new features.
  • More neurons per layer also add learning power, because each passes a slightly different line or shape forward.

With deeper layers, you learn more and more complicated non-linear combinations of features.

10.2 The forward pass

A forward pass is one trip of the data through the network: inputs → layer 1 → layer 2 → … → output. Each layer does a "mix and squish": mix = weighted sums of its inputs, squish = the activation. You computed one by hand in Section 9.2.

Preview of training (next part)

Training repeats: forward pass → compare the prediction with the truth using a loss → back-propagation computes how each weight affected the loss → gradient descent updates the weights. Data must be labelled for this kind of supervised learning. The playground in Section 11 does exactly this, one mini-batch at a time.

10.3 The cost: neural networks are black boxes

  • Thousands of weights interact; nobody can read off why the model made a decision, and there is no built-in "feature importance" as with trees.
  • A biryani analogy: the flavour comes from the whole blend. A pinch of kesar (saffron) changes flavour and colour a lot, yet you can't credit the dish to one ingredient. Deep-layer features are likewise combinations of combinations.
  • That is why regulated fields such as finance (for example, high-frequency trading) often prefer small, explainable models: a firm may have to justify a model's decisions, even in court.
Going further

Post-hoc tools such as SHAP, LIME and integrated gradients estimate how much each input influenced a prediction. They are approximations, so networks remain far less transparent than linear models or trees.

10.4 Why neural networks took off: GPUs

  • Neural-network maths is mostly matrix multiplication, which can be heavily parallelised.
  • GPUs follow SIMD (single instruction, multiple data): the same operation (for example multiply) runs on many numbers at once.
  • Back-propagation was popularised in 1986 by Rumelhart, Hinton and Williams, long after Rosenblatt's perceptron (1958), but large networks stayed impractical to train for decades.
  • AlexNet (2012, Krizhevsky, Sutskever and Hinton) had about 60 million parameters and was trained on GPUs. It wasn't the first CNN (LeNet came earlier) but it won the ImageNet competition by a wide margin and started the deep-learning boom.

Depth turns lines into curved, closed decision regions. The price is interpretability; GPUs are what made training practical.

12 The output layer: binary vs multi-class

Hidden layers usually share one activation; the last layer often uses a different one chosen for the task. Evaluation metrics don't change: accuracy, precision, recall, F1 score, as in classical ML.

One output neuron with sigmoid gives a probability; above 0.5 means "yes".

Example: the touch neuron gives z = −1.0 for a hot iron → σ(−1.0) = 0.269 → 26.9% < 50% → "don't touch".

In other words: combine logistic-regression units across multiple layers, with multiple units per layer, and you get a neural network with sigmoid activations.

One output neuron per class, then softmax turns the raw scores (logits) into probabilities that add up to 1.

Example: scores CAT 2.0, DOG 1.0, BIRD 0.1 → ez = 7.3891, 2.7183, 1.1052; sum = 11.2125 → probabilities 0.659, 0.242, 0.099.

softmax(zᵢ) = ezᵢ / Σⱼ ezⱼ

A medical-imaging example with four brain-scan classes:

13 Lab: a neuron, softmax and loss in NumPy

13.1 A single neuron

import numpy as np

class SimpleNeuron:
    def __init__(self, n_inputs=2, weights=None, bias=None):
        if weights is None:                       # small random weights by default
            self.weights = np.random.randn(n_inputs) * 0.01
        else:
            self.weights = np.array(weights)
        self.bias = 0.0 if bias is None else bias

    def sigmoid(self, z):
        return 1 / (1 + np.exp(-z))               # squashes any z into (0, 1)

    def process(self, inputs):
        z = np.dot(self.weights, inputs) + self.bias   # Step 1: weighted sum + bias
        return self.sigmoid(z), z                      # Step 2: activation

    def decide(self, inputs, threshold=0.5):
        probability, z = self.process(inputs)
        return probability >= threshold, probability, z

Pitfalls in this code

Overwritten weights: SimpleNeuron(n_inputs=3) creates three small random weights, which the next line replaces. If your constructor prints them, the printout is misleading: those weights are never used.

Thresholds: decide() uses >= 0.5, so don't switch to > 0.5 elsewhere. They only differ at exactly 0.5, but be consistent.

13.3 Many neurons at once: a layer as a matrix

Store all of a layer's weights in one weight matrix W of shape (features, neurons); W[i, j] is the weight from input i to neuron j. One matrix multiplication X @ W + b computes every neuron for every sample at once, replacing two nested loops.

class MultiClassNetwork:
    def __init__(self, n_features=2, n_classes=3):
        self.W = np.random.randn(n_features, n_classes) * 0.01   # shape (2, 3)
        self.b = np.zeros((1, n_classes))                        # shape (1, 3)

    def softmax(self, Z):                          # forget this -> AttributeError
        e = np.exp(Z - Z.max(axis=1, keepdims=True))      # stable version
        return e / e.sum(axis=1, keepdims=True)

    def forward(self, X):                          # X: (n_samples, n_features)
        Z = X @ self.W + self.b                    # every neuron, every sample at once
        return self.softmax(Z)
Bug to avoid

If forward() calls self.softmax(Z) but the class never defines softmax, Python raises AttributeError: 'MultiClassNetwork' object has no attribute 'softmax'. The version above includes it.

13.4 Loss functions

A loss function is the network's report card: low loss = good predictions, high loss = bad ones. For classification it is log loss / cross-entropy.

Binary: Loss = −[ y·log(ŷ) + (1 − y)·log(1 − ŷ) ]

Multi-class: Loss = −log(p of the true class)

def binary_cross_entropy(y, y_hat):
    return -(y * np.log(y_hat) + (1 - y) * np.log(1 - y_hat))

binary_cross_entropy(1, 0.9)   # 0.1054  (right and confident: small loss)
binary_cross_entropy(1, 0.1)   # 2.3026  (wrong and confident: big loss)

Cross-entropy on a batch of three samples:

def softmax(z):
    e = np.exp(z - np.max(z, axis=1, keepdims=True))   # subtract max: no overflow
    return e / np.sum(e, axis=1, keepdims=True)

scores = np.array([[2.0, 1.0, 0.1],     # sample 1 (true: CAT)
                   [0.5, 2.5, 0.5],     # sample 2 (true: DOG)
                   [1.0, 1.0, 1.0]])    # sample 3 (true: BIRD)
labels = np.array([0, 1, 2])

probs  = softmax(scores)
losses = -np.log(probs[range(3), labels])   # cross-entropy = -log(p of true class)
print(losses.round(4), losses.mean().round(4))

Two traps

Ties: for sample 3 all three probabilities are equal, yet np.argmax returns index 0 (CAT): it just picks the first index on a tie. The model has no preference.

Overflow: the naive softmax np.exp(z) / np.sum(np.exp(z)) breaks on large scores: for [1000, 1, 0] it returns [nan, 0, 0]. Subtracting the max first, as above, gives the correct [1, 0, 0].

13.5 Exercise: a 2-layer forward pass

Write just the forward pass of a small two-layer network in NumPy: 2 inputs → 3 hidden ReLU neurons → 1 sigmoid output. Try it before opening the solution.

Solution (verified by running it) 
import numpy as np
relu    = lambda z: np.maximum(0, z)
sigmoid = lambda z: 1 / (1 + np.exp(-z))

x  = np.array([0.5, -1.0])                 # one sample, 2 features
W1 = np.array([[0.2, -0.4,  0.1],          # 2 inputs -> 3 hidden neurons
               [0.6,  0.3, -0.5]])
b1 = np.array([0.1, 0.0, -0.1])            # one bias per hidden neuron
W2 = np.array([[0.7], [-0.2], [0.5]])      # 3 hidden -> 1 output neuron
b2 = np.array([0.05])

a1 = relu(x @ W1 + b1)       # layer 1: mix (weighted sum), then squish (ReLU)
y  = sigmoid(a1 @ W2 + b2)   # layer 2: mix, then squish (sigmoid -> probability)
print(a1, y)

14 FAQ

Does a neural network overfit with little data?

Question: Would a network overfit on a small dataset?

Answer: That's the main risk. With little data, prefer classical ML / GBDT; use a neural network when you have more data. (Try the noise slider in the playground to watch overfitting happen.)

More neurons = more accuracy?

Question: Do more neurons always mean more accuracy?

Answer: No. More neurons add capacity, but also cost and overfitting risk. Choosing the right size is covered in a later part.

How are the weights decided?

Question: How are the weights decided and changed?

Answer: They start random. Then the gradient of the loss with respect to each weight is computed and the weights are updated with gradient descent. Biases are learned the same way.

How does the activation function affect performance?

Question: How does the choice of activation change the results?

Answer: Each activation has a different derivative, so gradients, and therefore learning, behave differently. Sigmoid gives very small gradients in hidden layers (playground preset 6).

Can a neural network take any kind of data?

Question: Can a neural network accept tabular data, images, text, sound…?

Answer: Yes, anything numeric. For images, a special form called a CNN works best: you feed it labelled images directly, with no feature engineering.

Does the data need labels?

Question: Does the data have to be labelled?

Answer: For supervised learning, yes: the network learns by comparing its output with the labels.

Is the black box really the only option for images?

Question: Couldn't we use polynomial features instead of a black-box network for images?

Answer: Not in practice. Nobody can hand-create the set of features that captures what an image means, so a neural network is the practical option. For tabular data it often isn't worth it.

What maths should I brush up on?

Question: What helps most for the next parts?

Answer: Calculus (derivatives and the chain rule) for back-propagation, plus basic linear algebra (matrix multiplication) for layers.
